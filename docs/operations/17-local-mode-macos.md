# Local mode on macOS — runbook (C-06)

**Updated:** 2026-11-14. **Applies to:** the macOS edition (ADR-079) and local development on Apple Silicon.

This runbook sets up a Mac so Web Content Flow can use a model running on the same machine, with no cloud key. Read the status first: local models are **evaluated, not yet active**.

## Status — what works today

| Capability | State |
|---|---|
| App, worker and PostgreSQL running locally | ✅ works (see [16-development-handoff.md](16-development-handoff.md)) |
| Generation in the app with the deterministic mock | ✅ works, no key needed |
| Ollama / OpenAI-compatible (MLX) adapters | ✅ implemented (C-02, C-03) |
| `pnpm ai:health` — server up and model pulled | ✅ |
| `pnpm eval:ai` — quality and speed of a local model, 9 cases across all seven modules | ✅ |
| **App jobs generated by a local model** | ❌ **blocked by design** — see "Before jobs can use a local model" |

Local models are registered with `status: "evaluation"` and `persistedProvider: null`, so the router never sends a job to them (ADR-077). Configuring `AI_OLLAMA_*` makes them available to `ai:health` and `eval:ai` only.

## Requirements

- Apple Silicon (M1 or later). Tested on Apple M4, 32 GB.
- Memory: 16 GB minimum for a 4B model; 24–32 GB for the 12B primary candidate alongside the app, PostgreSQL and a browser.
- Disk: about 8 GB per 12B model, 4 GB per 4B model, plus the app.
- macOS with Homebrew.

## 1. Install and start Ollama

```bash
brew install ollama
brew services start ollama
```

Ollama listens on `http://127.0.0.1:11434` and starts with the Mac. Stop it with `brew services stop ollama`.

## 2. Pull the candidate model

```bash
ollama pull gemma4:12b-it-qat
```

Current recommendation (see [48-local-model-evaluation-macos.md](../technical/48-local-model-evaluation-macos.md)):

| Model | Use | Structured mode |
|---|---|---|
| `gemma4:12b-it-qat` | primary candidate | `native_schema` |
| `qwen3.5:4b` | not recommended (invents product attributes) | `prompted` |
| `qwen3.5:9b` | dropped (misses length limits) | `prompted` |

## 3. Configure `.env`

```bash
AI_OLLAMA_BASE_URL=http://127.0.0.1:11434
AI_OLLAMA_MODEL=gemma4:12b-it-qat
AI_OLLAMA_STRUCTURED_MODE=native_schema
AI_OLLAMA_THINK=false
```

Keep `AI_PROVIDER_DEFAULT=MOCK` and `AI_REAL_GENERATION_ENABLED=false` unless you also want the OpenAI path. `AI_OLLAMA_BASE_URL` and `AI_OLLAMA_MODEL` must be set together.

- `qwen3.5` models need `AI_OLLAMA_STRUCTURED_MODE=prompted`: Ollama answers "structured output is unavailable" to a schema for them.
- Leave `AI_OLLAMA_THINK=false`: with thinking on, the model spends its output budget reasoning and returns no JSON.

**MLX instead of Ollama:** run an OpenAI-compatible server such as `mlx_lm.server --model <repo> --port 8080`, then set `AI_OPENAI_COMPATIBLE_BASE_URL=http://127.0.0.1:8080`, `AI_OPENAI_COMPATIBLE_MODEL=<repo>` and `AI_OPENAI_COMPATIBLE_STRUCTURED_MODE=json_mode` (or `prompted`). Not evaluated yet.

## 4. Check the runtime

```bash
pnpm ai:health
```

Expected: `ollama  ok  gemma4:12b-it-qat  <ms>`. Other results:

| Status | Meaning | Fix |
|---|---|---|
| `unreachable` | the server is not answering | `brew services restart ollama` |
| `model_missing` | the model is not pulled; the line lists what is | `ollama pull <model>` or fix `AI_OLLAMA_MODEL` |
| `not_configured` | base URL or model is empty | step 3 |

## 5. Evaluate on this Mac

```bash
pnpm eval:ai --runtime ollama --samples 5
pnpm eval:ai --runtime ollama --samples 3 --cases calendar.editorial_week
```

- The run checks `ai:health` first and stops in seconds if the model is missing.
- A full run (9 cases × 5 samples) takes about an hour for the 12B model; video and calendar are the slowest cases. Reports land in `eval-reports/` (git-ignored); summarise them in `docs/technical/48-local-model-evaluation-macos.md`.
- Exit code 0 = PASS, 1 = FAIL on a threshold, 2 = could not run.

## Before jobs can use a local model

Each step needs the product owner's approval:

1. The candidate passes the suite on the edition's hardware with ≥ 20 samples per case, after a human review of the generated text.
2. Peak memory is measured with the app, worker, PostgreSQL and model running together.
3. The ADR-070 enum step: an **irreversible** `ALTER TYPE` adds the local provider to `GenerationProvider`, so jobs can record it.
4. The registry entry moves from `status: "evaluation"` to `active` with a `persistedProvider`, and a task policy names it.

Until then, the app keeps generating with the mock (or OpenAI when configured), and local models remain an evaluation tool.

## Troubleshooting

- **Requests time out on the first call:** loading a 12B model into memory takes 10–30 s; later calls are faster while Ollama keeps it loaded (5 minutes by default).
- **The Mac slows down during a run:** the model uses most of the GPU; close heavy apps or run evaluations with `--cases` one at a time.
- **Empty or truncated JSON:** check `AI_OLLAMA_THINK=false` and the structured mode for the model family.
